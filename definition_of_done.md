# Definition of Done (DoD)

A task, user story, bug fix, or epic is considered **Done** when all of the following criteria are met.

## Functional Completion
- [ ] All acceptance criteria (Gherkin scenarios) are met.
- [ ] Behaviour matches the user story or task objective.
- [ ] No regressions introduced.
- [ ] If sound effects are needed, they have been recorded and added

## Code Quality
- [ ] Code follows project style and conventions.
- [ ] Code is readable, maintainable, and appropriately commented.
- [ ] Dead code, debug logs, and temporary hacks removed.

## Testing
- [ ] Automated tests added or updated (where applicable).
- [ ] All tests pass locally and in CI.
- [ ] Edge cases covered.

## Documentation
- [ ] README, Notion docs, or inline comments updated if behaviour changed.

## Review & Approval
- [ ] PR reviewed and approved by at least one team member.
- [ ] Feedback addressed.
- [ ] Issue linked to the PR (auto‑close enabled where appropriate).

## Integration
- [ ] Changes merged into the main branch.
- [ ] No unresolved merge conflicts.
- [ ] Feature flags or config updated if needed.

## Project Tracking
- [ ] Issue moved to “Done” in GitHub Projects.
- [ ] Epic progress updated (if applicable).

---

This checklist ensures consistent quality across all repos and contributors.
